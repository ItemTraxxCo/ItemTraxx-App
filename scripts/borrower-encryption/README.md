# Borrower backfill (local implementation only)

Do not run this against staging or production until the SGW, workspace keys, access controls, recovery process and integration tests have been reviewed and the database migration for the writer freeze is deployed. This script does not remove or null legacy columns. Previously captured backups and logs may still contain plaintext.

`run-backfill.mjs` accepts exactly one workspace UUID plus `--execute --writers-paused`. Configure `ITX_SUPABASE_URL`, `ITX_SECRET_KEY`, and `ITX_SGW_INTERNAL_SECRET` through the local environment, never on the command line. The gateway address is fixed to `https://sgw.itemtraxx.com`. The script processes up to 50 rows per page, encrypts and decrypts each record, conditionally writes only if its plaintext is unchanged, reads back and decrypts again, and limits its operation rate. On a resumed run it verifies all encrypted records and their borrower-ID blind indexes, including archived records. It stops on missing IDs, inconsistent or unavailable ciphertext, collisions, changed rows, or gateway/database failures. Output excludes borrower data.

Before running, an authorized operator must activate the freeze for the target workspace using the service-only `set_borrower_write_freeze(workspace_id, true)` RPC. Its transaction waits for in-flight borrower writes; subsequent borrower inserts, updates, and deletes are rejected, including direct service-role writes. The service-only backfill RPC is the sole exception. The runner checks the freeze repeatedly and the database checks it again atomically for every backfill write. `--writers-paused` remains an explicit operator acknowledgement, not the enforcement mechanism. Keep the freeze active through verification and the separately planned read/write cutover; disabling it before cutover allows legacy plaintext writes again. A failed or interrupted run leaves the freeze active and can be resumed.

The guard uses a pre-existing, locked state row for each workspace and supports `READ COMMITTED`, `REPEATABLE READ`, and `SERIALIZABLE` transactions. At stronger isolation levels, a transaction with a snapshot older than a concurrent freeze-state change can fail with SQLSTATE `40001`; callers must retry the entire transaction. A missing state row fails closed. Workspace creation initializes the row and frozen workspaces cannot be deleted.

For an isolated local Supabase stack with the migration applied, run `supabase/tests/borrower_write_freeze_assertions.sql` against its database. The multi-connection race test is opt-in: set `ITX_LOCAL_FREEZE_TEST_DB_CONTAINER` to the local database container name and run `node scripts/borrower-encryption/freeze-concurrency.integration.mjs`. Both use synthetic records; never point the concurrency test at a hosted database.

The currently deployed legacy schema contains `username` and `borrower_id` only; those values become the encrypted username/display name and external borrower ID. Email requires a future migration source. This implementation does not confirm that all other plaintext copies, backups, logs, analytics, offline packs, or other data paths are clean, and it must not be used as sole evidence to drop plaintext fields.
